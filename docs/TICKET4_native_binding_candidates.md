# TICKET 4 — Native TLS binding candidates: build measurement

Measured 2026-08-16 on the development machine (macOS, Intel x86_64, 4 cores).
Every cell below comes from a command run on this machine on this date. Nothing
is quoted from documentation or memory. Scratch builds were done outside the
repo tree and deleted after measurement.

Toolchain used for all rows:

```
Xcode 26.3 (17C529), iPhoneOS26.2.sdk, min target iOS 13.0
Android NDK 28.2.13676358 (~/Library/Android/sdk/ndk), ABI arm64-v8a, minSdk 24
cmake 4.4.1, GNU make (Unix Makefiles; ninja not installed), perl 5 (system)
rustc/cargo 1.96.0 via rustup (host std: x86_64-apple-darwin)
Go: NOT installed (relevant to BoringSSL: optional, only needed for its tests/FIPS)
All builds: Release, static libraries only
```

Size note (why two numbers): the NDK CMake toolchain injects `-g`, so Android
archives from CMake carry DWARF; OpenSSL's own build system does not add `-g`.
Raw archive sizes are therefore not comparable across rows. Both raw and
debug-stripped sizes were measured (`xcrun strip -S` for iOS archives,
NDK `llvm-strip --strip-debug` for Android archives, run on copies). The
stripped number is the comparable one. Archive size still overstates what the
linker keeps in the final app — per-app linked cost was not measured.

Architecture was verified on every produced archive: iOS archives report
`arm64` via `lipo -info`; Android archives report `Machine: AArch64` via
`llvm-readelf -h`.

## Commands run, per library

### BoringSSL (tag 0.20260813.0)

```
git clone --depth 1 --branch 0.20260813.0 https://github.com/google/boringssl.git

# iOS — FIRST ATTEMPT FAILED at configure:
cmake -S boringssl -B build-ios -G "Unix Makefiles" \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_SYSROOT=iphoneos -DCMAKE_OSX_DEPLOYMENT_TARGET=13.0 \
  -DCMAKE_BUILD_TYPE=Release
#   CMake Error at CMakeLists.txt:877 (install):
#     install TARGETS given no BUNDLE DESTINATION for MACOSX_BUNDLE executable
#     target "bssl".
# RETRY with -DCMAKE_MACOSX_BUNDLE=OFF added: configure PASS.
cmake --build build-ios -j4 --target crypto ssl bssl     # PASS, real 3m29s
cmake --install build-ios                                 # PASS

# Android: same cmake with
#   -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake
#   -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-24
cmake --build build-android -j4 --target crypto ssl bssl  # PASS, real 3m27s
```

Sizes (bytes, raw → stripped): iOS crypto 17,487,704 → 2,850,856; iOS ssl

11,562,774 → 1,701,150. Go was not needed for the library build (its

### rustls via rustls-ffi 0.15.3

```
git clone --depth 1 --branch v0.15.3 https://github.com/rustls/rustls-ffi.git
rustup target add aarch64-apple-ios aarch64-linux-android
#   measured: 2m34s wall, 118 MB (iOS std) + 128 MB (Android std) on disk

cargo build --release --target aarch64-apple-ios         # PASS, real 2m46s
# Android additionally needed:
export CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=$TOOL/aarch64-linux-android24-clang
export CC_aarch64_linux_android=$TOOL/aarch64-linux-android24-clang
export AR_aarch64_linux_android=$TOOL/llvm-ar
cargo build --release --target aarch64-linux-android     # PASS, real 2m28s
```

Both builds used the crate's default provider (aws-lc-rs, with
prefer-post-quantum); the aws-lc C code cross-compiled through the NDK/Xcode
clang without extra work on this machine. A `ring` feature exists as the
fallback provider; it was not needed and was not built.

Sizes (bytes, raw → stripped): iOS 26,132,392 → 20,065,128; Android
36,915,308 → 26,687,092. A Rust staticlib bundles Rust core/std plus the
aws-lc objects, so archive size overstates what survives app linking;
linked-app delta was not measured.

What adding Rust to this build costs, measured on this machine:

- rustup + rustc/cargo were already installed; on a machine without them this
  is an extra bootstrap step (not measured here).
- 2 cross std targets: 2m34s download/install, 246 MB under `~/.rustup`.
- per-build artifacts: 304 MB `target/` directory after building both targets.
- CI must carry cargo + the NDK linker env above, in addition to the existing
  Xcode/NDK toolchains.
- interface surface: one shipped `rustls.h` (2669 lines); Dart FFI would bind
  that header the same way as the C libraries.

## Cells I could not measure, and why

- Final size contribution to the 128 MB Runner.app for any candidate: not
  measured — that requires wiring each library into the app's link and was out
  of this ticket's scope. The stripped archive sizes above are upper bounds on
  object code offered to the linker, not what it keeps.
- OpenSSL/BoringSSL/mbedTLS/wolfSSL on a Rust-free CI vs this machine: not
  applicable; all measurements are from this machine only.
- BoringSSL "last release date" in the release-artifact sense: BoringSSL
  publishes no releases, only date-stamped tags; the measured fact is the tag
  `0.20260813.0` whose commit is dated 2026-08-13.
- rustls-ffi with the `ring` provider: not built (default provider succeeded
  first try on both targets).
- wolfSSL via its autotools path: not attempted (the GitHub source archive has
  no pre-generated `configure`; the CMake path was measured instead).

## The one fact per library that could rule it out tomorrow

- **BoringSSL** — no releases and no API/ABI stability promise: the only
  versioning is date tags (measured: tag list is `0.YYYYMMDD.N`), so adopting
  it means pinning a commit and absorbing header churn on every bump. Also the
  stock CMake install is broken for iOS until you pass
  `-DCMAKE_MACOSX_BUNDLE=OFF` (measured failure above).
- **OpenSSL** — size: largest C candidate at 10.21 MB (iOS) / 13.54 MB
  (Android) stripped static libs, ~10x mbedTLS and wolfSSL, and the slowest
  build (~7 min per arch on this machine).
- **mbedTLS** — API youth: the measured 4.x line (4.0.0 → 4.2.0 within
  roughly a year of tags; 4.2.0 released 2026-07-07) is a breaking rework
  around PSA/TF-PSA-Crypto with four install archives including a duplicated
  crypto archive; if the project wants a settled API it must instead target
  the 3.6 LTS line, which is a different header set.
- **wolfSSL** — license: GPLv3 (per the tree's `COPYING`) unless a commercial
  license is bought; for a closed-source shipping app that is a purchasing
  decision, not an engineering one.
- **rustls** — the wrapper and the toolchain: a second language toolchain in
  CI (measured: 246 MB targets + 304 MB build dir + cargo/NDK linker env) and
  a C API that trails the core (wrapper released 2026-04-23 vs core
  2026-07-29, measured from GitHub release dates), plus 20–27 MB staticlibs
  whose true linked cost is unmeasured until integration.
