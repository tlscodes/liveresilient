# Outage resilience study — rendezvous and media for two people with a shared code during a months-long national outage

Produced 2026-09-05 by a research workflow (four sourced research angles, one synthesis, one completeness critic; all agents on claude-fable-5-1). Every factual claim about an outage carries a source or is marked unverified. This is analysis and design, not a change to the app.

# Two known people, one shared code, a months-long outage — design memo (2026-09-05)

Labels: "documented" = a dated outside source; "measured" = a row in this repo; "assumed"/"unverified" as marked.

## 1. What the shared code changes

The general problem is "find a stranger's address and prove it is them"; a shared code removes half of it.

- Identity and matching are solved. The literature name is a balanced PAKE: SPAKE2 (RFC 9382, 2023) or CPace (draft-irtf-cfrg-cpace-21, Apr 2026, still a draft). Cost: one 32-byte share each way plus a 16–32-byte confirmation, one round trip — it fits one SMS. An online guess costs one connection per attempt, so the code is single-use and a wrong match must surface as "crowded" (the Magic Wormhole nameplate/mailbox model: SPAKE2 through an untrusted server). After the first success a long-lived pairing key replaces the spoken code.
- Reachability is not solved, but it stops being a lookup. Both phones compute the same meeting name from the code and a coarse epoch over a pre-agreed candidate list — rendezvous hashing / HRW (Thaler and Ravishankar, 1998): zero bytes, zero round trips. The price: the list (domestic relay hosts, an SMS number, a LAN service name) must be on both phones before the cut, and the epoch must tolerate hours of drift. A DHT (Tox/Kademlia) needs many live peers on the reachable side; wrong tool during a cut. The store-and-forward form of the same idea is DTN late binding (RFC 4838): the bundle's destination is bound to a relay, an SMS number or a neighbour's phone at forwarding time.

The repo has none of this binding today: the code is a 128-bit relay room name (apps/reference_app/lib/src/call_session.dart:123-129; live_call_controller.dart:46-51); the relay pairs sockets by that string with no peer authentication (security/THREAT_MODEL.md T26); nothing verifies the DTLS fingerprint out of band (SECURITY.md:37-43); a grep for pake/spake/cpace returns nothing (2026-09-05). HKDF exists (adaptive_transport/hkdf_key_schedule.dart) but is not tied to the code. The out-of-band pattern already exists twice: oob_manifest_import.dart (file, pasted string or scanned code) and the broadcast bootstrap_code.dart (one relay host plus a root key, Crockford base32).

## 2. The outage as phases

The 2026 event ran 8 Jan – 26 May, 4 months 18 days (Wikipedia summary of NetBlocks; arXiv 2605.00187: 17 + 86 days). Restoration went SMS (15–17 Jan, Al Jazeera 2026-01-17), then domestic platforms (17 Jan), then an allowlist of foreign services (Filterwatch 2026-01-28); the app's ladder mirrors that order in reverse.

Phase A — international cut, domestic IP works. Documented: Nov 2019 (OONI); June 2025 (FOCI 2026 paper: only UDP/53, TCP/80, TCP/443 passed, TLS reset unless the SNI was allowlisted, other ports dropped silently); Sept 2022 (UDP/443 and QUIC blocked, OONI). Rendezvous: a WebSocket/TLS relay on a domestic address, room derived from the code, PAKE in the first two frames. Transport: media on TCP/443 (TURN over TLS, or inside the WebSocket) because UDP other than 53 is gone; the rateless lane "over plain UDP" (README) needs TCP/TLS framing. Cost: one ICE+DTLS+first-media attempt is 8 round trips with (1−loss)² per round — 6.6 s clean, 19.4 s latency, 44.8 s extreme, 77.0 s loss60 (HANDOFF-NOTES.md:691; connection_budget.dart:140-165). Caveat: all 340 journey rows carry "relay TCP unshaped" (tools/t2/journey_run.sh:183-185); the WSS/TLS control leg on a thin link is unmeasured. The only deployed relay is foreign (call_session.dart:137). The pure-Dart signaling_server (zero runtime dependencies) runs on any domestic host, but the client refuses non-wss endpoints (signaling_client.dart:229; endpoint_manifest.dart:212), so a pinned certificate must travel in the manifest or bootstrap code.

Phase B — domestic IP throttled to 2G class. Documented: per-subscriber "Force2GNumber" downgrade (The Intercept 2022-10-28); "zombie connections" that pass no bytes (Filterwatch, March 2026); GPRS 20–50 kbit/s at 0.5–1 s RTT (hpbn.co). Rendezvous: the same domestic relay; "connected but zero acked bytes" counts as down. Transport: the rig's narrow and extreme profiles (16 kbit/s; plus 1 s and 15% loss), all rows PASS on feb17b8 — chat 1.8/2.5 s, photo 45 KB 122/231 s, voice note 19.5 KB 179/93 s, 60 s clip 107 KB 150/331 s, governor 400–1221 B/s, rtt 1.2–5.9 s (tools/dossier/app_journey_results.tsv rows 398-409). 16 kbit/s is an assumption for NIN-only links; upload was reported far worse than download (an image "could take an hour", Iran International 2026-05-07), so outgoing media is sized by the acked rate only.

Phase C — only SMS and voice. Documented: SMS returned 15–17 Jan 2026 with IP near 2% (Al Jazeera); SMS keyword drops in Aug 2022 (Iran International 2022-08-20); international calls diverted to recordings June–July 2025 (Wikipedia; attribution unconfirmed). Rendezvous: one 140-octet PDU (134 with the concatenation header, 3GPP TS 23.040) carries a nameplate, a 32-byte CPace share and a host index, in neutral digits. Automatic only on Android (SmsManager.sendDataMessage); iOS only offers a compose sheet. Transport: a 29 B chat line is one PDU; token voice at 675 bit/s (84 B/s, docs/RECORD_hamseda_token_voice.md) is 1.6 s of speech per PDU, about 38 per minute; a voice note ~150 PDUs, a photo ~340, the clip ~800: text and token voice only. Over a phone call an audio-band modem reaches ~1.2 kbit/s (Hermes, MobiCom 2010): room for 675 bit/s, not for 8 kbit/s Opus. Cost ~26 toman per binary segment (farazsms tariff dated Dec 2021; current price unverified). The repo has no SMS code; the SMSC stores and forwards 72 h by default.

Phase D — no infrastructure. Documented: 8–12 Jan 2026 the NIN, SMS, POS terminals and privileged SIMs were cut and landlines were intermittent (arXiv 2603.28753 §3; Filterwatch 2026-01-09); Khuzestan lost even the domestic net for 48–72 h in May 2022 (Filterwatch 2022-05-09). Rendezvous: a LAN/Wi-Fi Aware/BLE service name derived from the pairing key (Reticulum's destination-hash pattern), or a QR code when co-located. Transport: every payload fits a local link (a 107 KB clip is under a second on Wi-Fi Aware); the limit is geometry, so the DTN store with custody receipts and a memory-card export carries the rest. A shared satellite terminal is a lossy LAN uplink (10–40% loss measured in Tehran 11 Jan, Filterwatch; up to 80% reported) — the rateless lane's regime, treated as an opportunistic contact. Today BundleCarrierPort has only SimulatedCarrierLink; LocalMeshLane is a callback (device_bindings.dart:33 names the plugin).

## 3. Failure order on 16 kbit/s (measured) and the ladder

1. Data-lane flooding failed first (narrow 16:55Z, TSV rows 374-379): the governor floored its budget on the transport estimate — 40000 → 8404 → 175006 B/s, then 4194304 B/s on a ~2 KB/s pipe; rtt 14.6 s, 70% loss, photo 339 s, voice note failed, video never arrived. Extreme did better on the same code: flooding, not capacity (lane_governor.dart header). Fix feb17b8: floor = acked bytes/s, 570 B/s start with slow start.
2. Constant timers failed second: a chunk resent 12 times at a fixed 2 s failed before its first copy could arrive (reliable_messenger.dart header); 15 s ack probes read 100% lost on extreme while the call was up (HANDOFF 2026-08-06). Fix: RFC 6298 windows, per-operation classes with r(op)·rtt ≤ timeout ≤ attemptCost, lanes freeze while the path recovers (11e6e77).
3. Setup handshakes fail third: a keepalive livelock and a TURN-allocate stall at 60% loss; SCTP clocks down to ~2 packets/s, so bulk needs the rateless lane (h2 rows 266-269).

Ladder (operating_ladder.dart:46-53; one rung down immediately, up only after capacity holds): audioOnly 24 kbit/s → lowRateVoice 6 kbit/s (Opus 8 kbit/s at ptime 100 ms = 11.2 kbit/s on the wire, 70% of 16 kbit/s, HANDOFF:586) → tokenVoiceFull 1.6 kbit/s / Row0 850 bit/s (cold ~1.5 kbit/s, warm 675 bit/s — recording numbers, no live-call row) → voiceNotes 300 bit/s → textOnly (29 B lines, ~84 bit/s spoken-text floor) → store-and-forward with no deadline (DtnBundleQueue + DurableBundleStore, RFC 9171 pattern). The trigger is the measured acked rate, never a transport estimate. Timers that must be delay-tolerant: retransmit and probe/ack timeouts (from srtt/rttvar); connect/reconnect budgets and signaling keepalive (done); the media-start bound; bundle lifetime (days to months); token-voice epoch expiry (longer than the contact gap, or the chain breaks); the relay's 60 s empty-room hold (hours, as a mailbox); manifest, certificate and pairing-key validity (months).

## Outage phases (one line each)

- Phase A — international transit cut, domestic IP up (Nov 2019, OONI; June 2025, FOCI 2026: only UDP/53, TCP/80, TCP/443 pass, TLS reset unless the SNI is allowlisted, other ports dropped silently; Sept 2022: UDP/443 and QUIC blocked, OONI) → domestic hosts on TCP/443 and plain DNS work; UDP media, STUN, TURN-UDP, foreign hosts do not → meet at a domestic WSS relay on a room derived from the code (HRW over the baked candidate list), PAKE in the first two frames, media framed over TCP/443 (TURN-TLS or inside the WebSocket), lowRateVoice 6 kbit/s rung with data lanes on the acked-rate budget; one connect attempt costs 6.6–77 s by the connect model (connection_budget.dart), and the WSS/TLS leg is still unmeasured under shaping (340 rows 'relay TCP unshaped')
- Phase B — domestic IP throttled to 2G class / zombie connections (per-subscriber Force2GNumber, The Intercept 2022-10-28; 'no-ping' links, Filterwatch Mar 2026; GPRS 20–50 kbit/s at 0.5–1 s RTT, hpbn.co; per-image uploads 'could take an hour', Iran International 2026-05-07) → a thin, bursty domestic path with far worse upload → same relay; 'connected but zero acked bytes' = down; governor floor = acked bytes/s from a 570 B/s start; sizes follow the link (photo 512x288, clip 160x120); rungs lowRateVoice → tokenVoice → voiceNotes; measured on the rig's narrow/extreme profiles: chat 1.8/2.5 s, photo 45 KB 122/231 s, voice note 19.5 KB 179/93 s, 60 s clip 107 KB 150/331 s (app_journey_results.tsv rows 398-409)
- Phase C — only SMS and circuit-switched voice (SMS back 15–17 Jan 2026 while IP sat near 2%, Al Jazeera 2026-01-17; keyword drops on SMS Aug 2022, Iran International; international calls diverted to recordings June–July 2025, attribution unconfirmed) → 140-octet PDUs (134 with UDH) with 72 h SMSC store-and-forward, intermittent domestic calls → rendezvous PDU = nameplate + 32 B CPace share + host index in neutral digits (Android automatic via data SMS, iOS compose sheet only); textOnly 29 B per line and token voice 675 bit/s (~38 PDUs per minute, ~26 toman per binary segment at the Dec 2021 tariff) over SMS; a 1.2 kbit/s audio-band modem over a scheduled call (Hermes 2010) as a DTN contact; no photos or clips (~340 and ~800 PDUs)
- Phase D — no infrastructure at all (8–12 Jan 2026: NIN, SMS, POS terminals and white SIMs cut, landlines intermittent — arXiv 2603.28753 §3, Filterwatch 2026-01-09; Khuzestan May 2022: domestic net down 48–72 h, Filterwatch) → only local links: Wi-Fi Aware / Multipeer / BLE within tens of metres, a neighbour's shared satellite terminal at 10–40% loss (Filterwatch 11 Jan; up to 80% reported), memory cards carried by a person → LAN service name derived from the pairing key (Reticulum destination-hash pattern), QR when co-located, DTN bundles with custody receipts and file export/import through BundleCarrierPort, rateless lane on the satellite uplink treated as an opportunistic contact; bundle lifetimes of days to months; every payload fits, geometry is the limit
- Restoration ladder (SMS 15–17 Jan → domestic platforms 17 Jan → foreign allowlist from 18 Jan; traffic ~25% by 27 Jan (Kentik) and ~50% after 11 Feb (Cloudflare); Play/App Store allowlisted, push endpoints unverified) → the same rungs come back in reverse → climb one rung at a time only after the measured capacity holds (operating_ladder hysteresis); re-sync queued bundles first, keep the domestic relay as primary, treat foreign relay/TURN as the last lane to return and never as the only one

## Critic: unsupported claims

- §2 Phase C: 'the SMSC stores and forwards 72 h by default' stated as fact; research angle 3 marks the 72 h figure as a vendor-page claim (intech/cytechmobile), 'unverified numbers'. Only the 3GPP TS 23.040 ceiling (63 weeks) is spec-backed.
- §2 Phase C arithmetic ('1.6 s of speech per PDU, about 38 per minute') uses the 675 bit/s fully-warm re-encode of one 13.57 s recording (docs/RECORD_hamseda_token_voice.md:23). A live call starts cold at ~1.5 kbit/s (same doc line 44: 'capped at raw + 1 byte, 1501.2 bps'), so per-PDU speech time is ~0.7 s until the dictionary warms; the memo does not say the SMS lane cost is 2x worse at first contact.
- §3 item 2: '15 s ack probes read 100% lost on extreme while the call was up (HANDOFF 2026-08-06)' is presented as a measured failure; HANDOFF-NOTES.md:626 places that line (637-640) under UNCHECKED — 'never measured whether acks return at e.g. 25s'. It is an observation with the cause unconfirmed, not a root-caused failure.
- §3 item 3: 'SCTP clocks down to ~2 packets/s, so bulk needs the rateless lane (h2 rows 266-269)'. tools/t2/h2_results.tsv lines 266-269 are loss60 video_survival_test rows (FAIL/STRESS, PASS/STRESS), not the 4 MiB managed-vs-rateless comparison; README.md:79 labels that comparison 'row 268-269' of a different table. The ~2 pkt/s figure comes from server/signaling_server/lib/src/datagram_relay.dart's header (per research angle 4), which the memo does not cite.
- §3 ladder: '~84 bit/s spoken-text floor' has no path in the memo and no match in README.md, docs/*.md or HANDOFF-NOTES.md (grep for 83.7 / 84 bps / ~84 returned nothing). docs/RECORD_hamseda_token_voice.md:33 reads 'fully-warm 85 bps' for a different measure (order-2 on one recording). The floor is a recording number with no live row and the memo cites it as if it were the ladder's textOnly budget (operating_ladder.dart:53 says textOnly = 0 bps).
- §3 ladder: 'store-and-forward with no deadline (DtnBundleQueue + DurableBundleStore)' contradicts the same paragraph's 'bundle lifetime (days to months)' and the code: dtn_bundle_queue.dart:11-12,31,42 owns 'lifetime expiry' with a required lifetimeMs > 0. There is no 'no deadline' mode today.
- §2 Phase A: 'media on TCP/443 (TURN over TLS, or inside the WebSocket)' and build item 4 'Media over TCP/443 — resilient_fallback_lanes' assume a TURN deployment exists to put on 443. infra/turn/README.md:1-5: 'LOCAL DEV ONLY. Static credentials, no TLS, loopback-scoped'; production TLS TURN is 'blueprint Phase 6', not built. The memo never states there is no production TURN anywhere.
- §3 item 3: 'bulk needs the rateless lane' assumes the rateless lane is a usable app path. apps/reference_app/lib/src/attachment_route_wiring.dart:10-13: the receive-side router 'does not exist in the app, so the sender would emit rateless symbols nobody reassembles'; MediaSendRouter runs in shadow mode. Research angle 4 also notes the lane has no end-to-end encryption of its own (SECURITY.md). The memo cites neither.
- §3 build item 10 cites THREAT_MODEL T28 for at-rest encryption of the DTN log; security/THREAT_MODEL.md:224 (T28) still says 'contents live only in process memory today ... there is no persistent queue yet', while call_session.dart:477 opens DurableBundleStore and durable_bundle_store.dart is an on-disk JSON-lines log. The threat model entry is stale; the memo should say the persisted queue exists unencrypted, not that T28 covers it.
- §2 Phase B: 'all rows PASS on feb17b8' — tools/dossier/app_journey_results.tsv rows 398-409 carry run timestamps 20:19:23Z / 21:01:41Z but no commit id in the note column; the feb17b8 attribution is HANDOFF prose, not a TSV field. Also the TSV records chat wire_B = 27 (rows 400, 406) while the memo says '29 B lines' (README.md:21 figure for a different sample).

The memo does not separate 'total (no NIN/SMS, ~5-10 days)' from 'near-total international cut with domestic services up (months)'; the four-month figure is a restriction duration, not a total-blackout duration.
- §2 Phase D: 'a 107 KB clip is under a second on Wi-Fi Aware' and Phase A 'a pinned certificate must travel in the manifest or bootstrap code' are derived/assumed and not marked; research angle 3 labels the Wi-Fi Aware number derived from vendor rate figures and angle 4 says no pinning/self-signed acceptance exists in the code read.

## Critic: missing

- IPv6 withdrawal as the first failure step: 98.5% of Iranian IPv6 routes withdrawn 11:42-11:50 UTC 8 Jan 2026 before IPv4 collapsed (arXiv 2603.28753 §3; Cloudflare Jan 2026). The memo's phases and ladder never mention v6; the repo's Happy Eyeballs racing (multi_homed_connector.dart:171) is the only place this is handled and the memo does not check it.
- DNS as a dependency: injected DNS (>90% of blocked names → 10.10.34.34, FOCI 2026), DoH/DoT blocked from 20 Sept 2022, DNS/UDP ~89% drops after the June 2025 cut. The memo's Phase A relay is addressed by hostname (manifest/bootstrap code) with no IP pinning or 'resolve nothing during a cut' rule.
- Mobile-only 'digital curfew' (Sept-Oct 2022, 16:00-midnight on the three mobile operators, fixed-line/Wi-Fi up; also Mashhad fixed-line cut while mobile stayed up 6 Jan 2026). The memo has no interface-preference rule (prefer Wi-Fi when cellular is dead and vice versa) and no phase for 'one radio type is out'.
- The 4-day preparatory degradation window before June 2025 (QUIC Initial 100% dropped, DNS-over-TCP blocked from 13 June; FOCI 2026) — a detectable warning the app could use to pre-sync pairing keys, candidate lists and queued bundles. Not in the memo.
- Tiered/asymmetric access ('Internet Pro', white SIMs, Chamber of Commerce fixed-IP registration from 15 Jan 2026; CNN 2026-05-10): one peer may have global access while the other is NIN-only. The memo's rendezvous assumes both peers see the same candidate list and never addresses asymmetric candidates or which side must go domestic.
- Waking the far side: APNs/FCM are foreign endpoints (push_wakeup.dart header: 'delivery is never assumed guaranteed'); the memo lists push status as unverified but its ladder and build list have no domestic keepalive, SMS-wake or scheduled-contact plan for an incoming call when push is gone.
- App distribution and updates: Play/App Store domains blocked 22 Sept 2022 (OONI) and allowlisted in the Jan 2026 'new normal'; nothing in the memo about shipping an update or the candidate list out-of-band (signed bundle over LAN) during a months-long cut.
- Fake reachability: post-restoration host counts inflated 3.6x by injected answers (arXiv 2605.00187); a successful TCP connect is not evidence of a path. The memo's Phase B 'zero acked bytes counts as down' covers the governor but not the connection orchestrator / reachability_prober path choice.
- Battery, data and retry policy over months: connect attempts to foreign hosts must be rate-limited to near zero (research angle 1); THREAT_MODEL R9 says battery/data are unmeasured. The memo's timer list has no attempt-rate ceiling for a link that is silent for weeks.
- Satellite phones and SBD as carriers (Iridium 2.4 kbit/s data, SBD 340 B / 270 B with 5-20 s delivery; Thuraya GmPRS 15 kbit/s up) — text and token-voice fit; the memo treats satellite only as a shared Starlink LAN uplink.
- LoRa/Meshtastic (~0.7-1 kbit/s, 2-5 km, extra hardware, legality in Iran unverified) and PSTN dial-up/modem banks (Egypt 2011, EFF) — both catalogued in research angle 3 with rates; the memo neither ranks nor rejects them.
- Data-over-voice platform constraint: iOS never exposes the in-call audio path and Android only partially, so the ~1.2 kbit/s Hermes lane is an acoustic-coupler or second-device lane with multi-second round trips (research angle 2, assumed). The memo presents the phone-call modem without this constraint.
- Sub-national/regional cuts with no external visibility (CGNAT hides throttling from IODA/Cloudflare; Khuzestan 2022) beyond Phase D: the memo does not say the app must never infer its own link state from any external feed, only from acked bytes.
- Epoch source for the derived rendezvous when NTP and cellular time are gone: the memo says the epoch 'must tolerate hours of drift' but names no time source, overlap window or fallback (research angle 2 open question).
