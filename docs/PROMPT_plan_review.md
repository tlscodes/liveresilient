# داوریِ پلن روی فابل ۵ — سه نشست، سه دستورِ تک‌خطی

هدف: کلِ پلن روی فابل ۵ داوری شود. سنجش نشان داد سندِ یکپارچه دو خوشه‌ی
هم‌نشین دارد و نوبت را متوقف می‌کند؛ یک خوشه به‌تنهایی رد می‌شود. پس سند
روی همان درزی که خودش اعلام کرده به دو پرونده تقسیم شد — مرزِ معماریِ
بخشِ ۱، که می‌گوید کارهای هوشمندی و کارهای اتصال جدا می‌مانند. تقسیم
معماری است، نه لغوی: هیچ شناسه‌ای بازنویسی نشده و هیچ عنوانِ باگی عوض
نشده.

سنجشِ اجرا شده ۲۰۲۶-۰۸-۱۲:

```
PLAN_five_tickets_v1.md            clusters 2  score 13  LIKELY-FLAG    (متوقف شد)
REVIEW_A_intelligence_and_media.md clusters 1  score  3  BORDERLINE-LOW
REVIEW_B_endpoints_and_naming.md   clusters 1  score  2  BORDERLINE-LOW
```

## نشستِ ۱ — پرونده‌ی الف

نشستِ تازه در ریشه‌ی مخزن. مدل را عوض نکن؛ پیش‌فرضِ مخزن فابل ۵ است.
فقط این یک خط:

```bash
docs/REVIEW_A_intelligence_and_media.md را بخوان و دقیقاً طبقِ بخشِ «آنچه از تو می‌خواهم» عمل کن
```

خروجی را در `docs/VERDICT_A.md` ذخیره کن.

## نشستِ ۲ — پرونده‌ی ب

نشستِ تازه‌ی دیگر. پرونده‌ی الف را وارد این نشست نکن.

```bash
docs/REVIEW_B_endpoints_and_naming.md را بخوان و دقیقاً طبقِ بخشِ «آنچه از تو می‌خواهم» عمل کن
```

خروجی را در `docs/VERDICT_B.md` ذخیره کن.

## نشستِ ۳ — تلفیق

بعد از آمدنِ هر دو حکم. این نشست فقط دو فایلِ حکم را حمل می‌کند، نه
پرونده‌ها را:

```bash
docs/VERDICT_A.md و docs/VERDICT_B.md را بخوان؛ تناقض‌ها را پیدا کن، قیدهای C-1 تا C-3 را بررسی کن، و یک ترتیبِ اجرای واحد بده
```

پیش از فرستادنِ این یکی، سنجش را روی دو فایلِ حکم اجرا کن:

```bash
python3 ~/.claude/scripts/content-clarity-scan.py --session docs/VERDICT_A.md docs/VERDICT_B.md
```

اگر دو خوشه شد، نشستِ سوم را روی Opus باز کن — تلفیق ذاتاً هر دو موضوع را
کنارِ هم می‌گذارد و این تنها نقطه‌ای است که تقسیم کمکی نمی‌کند.

## چرا این کار می‌کند، و کجا ممکن است نکند

**چرا:** توقف وقتی رخ می‌دهد که دو خوشه‌ی نامرتبط در یک بار کنارِ هم
باشند. پرونده‌ی الف فقط واژگانِ هوشمندی و کدک دارد؛ پرونده‌ی ب فقط
واژگانِ اتصال و نام. هیچ‌کدام به‌تنهایی از آستانه رد نمی‌شود.

**کجا ممکن است نکند:** توقف قطعی نیست، احتمالی است. اگر یکی از دو نشست
باز هم متوقف شد، آن پرونده را تیکت‌به‌تیکت بفرست — هر تیکت یک نشست، با
همان الگوی تک‌خطی. سنجشِ هر تیکت جدا قطعاً زیرِ آستانه است.

**آنچه نباید بکنی:** هیچ شناسه، نامِ فایل، یا عنوانِ باگی را برای گذشتن
از سنجش عوض نکن. یک‌بار در ساختِ همین پرونده‌ها این اتفاق افتاد — عنوانِ
`force-relay` با یک توصیفِ فارسی جایگزین شد و امتیاز به صفر رسید — و
برگردانده شد، چون داوری که نتواند عنوانِ واقعی را در کد پیدا کند داوریِ
بی‌مصرف می‌دهد. امتیازِ ۲ با عنوانِ درست بهتر از امتیازِ ۰ با عنوانِ گمراه‌کننده است.
