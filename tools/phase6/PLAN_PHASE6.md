## قدم ۱ — رمزنگاری سرتاسری لاین دیتاگرام (ارزش ۹.۵)

مسئله (از سند فنی، فصل ۷): مدیای تماس روی DTLS-SRTP رمز است، ولی لاین
دیتاگرام — همان مسیری که امشب متن/خبر/عکس/صوت/ویدیو از آن گذشت — رمز
سرتاسری ندارد و رله بایت‌ها را می‌بیند.

طرح: یک wrapper روی `DataChannelPort` که پیش از هر انتقال، یک توافق
کلید X25519 انجام می‌دهد؛ سمت پاسخ‌دهنده رونوشت دست‌دهی را با هویت
Ed25519 موجود امضا می‌کند و سمت آغازگر آن را در برابر کلید عمومیِ
pin-شده راستی‌آزمایی می‌کند. کلیدهای جهت‌دار با HKDF-SHA256 مشتق و
فریم‌ها با ChaCha20-Poly1305 مهر می‌شوند. ضدتکرار: شمارنده‌ی هر جهت با
پنجره‌ی ۶۴تایی (UDP جابه‌جا می‌رساند). دست‌دهی روی لاینِ پراتلاف با
بازارسال دوره‌ای تا مهلت مشخص.

محدودیت‌های صادقانه که در کد و سند نوشته می‌شوند: بدون ratchet
(یک جفت کلید موقت در هر نشست لاین)؛ آغازگر در v1 به پاسخ‌دهنده
احراز هویت نمی‌شود (اتاق‌ها با roomKey محدود شده‌اند).

سربار هر فریم داده: ۱ بایت نوع + ۸ شمارنده + ۱۶ MAC = ۲۵ بایت.
اثر روی جدول: هر ردیف با سربار تازه دوباره محاسبه و ثبت می‌شود.

```
verify: bash tools/phase6/gates/gate_p1_crypto.sh
exit 0 فقط وقتی: تست‌های واحد سبز (round-trip، رد امضای جعلی، رد تکرار،
دست‌دهی زیر ۶۰٪ اتلاف)، analyze صفر، و سربار اندازه‌گیری‌شده در
tools/dossier/crypto_overhead.tsv نشسته باشد.
```

## قدم ۲ — صف خروجیِ پایدار روی دیسک (ارزش ۹)

مسئله: در شبکه‌ی ۶۰٪ اتلاف پیام گاهی دقایقی در صف می‌ماند؛ اگر اپ
kill شود آن پیام از بین می‌رود. ماشین store-and-forward در تست‌ها هست،
دوامِ بین اجراها نیست.

طرح: ژورنالِ فقط-افزودنی روی دیسک (هر رکورد: طول، CRC، بایت‌های فریم،
وضعیت). بازیابی هنگام راه‌اندازی: رکوردهای ناتمام دور ریخته می‌شوند،
باقی دوباره صف می‌شوند. حذف پس از تأیید تحویل. سقف اندازه با هرس
قدیمی‌ترین‌ها و شمارنده‌ی حذف‌شده‌ها (سکوت ممنوع).

```
verify: bash tools/phase6/gates/gate_p2_queue.sh
exit 0 فقط وقتی: تست «نوشتن، kill، بازخوانی، تحویل» سبز باشد و تست
خرابیِ نیمه‌نوشته (فایل بریده‌شده) رکورد سالم را حفظ کند.
```

## قدم ۳ — UX پلکانی پیش‌فرض (ارزش ۹)

مسئله (عدد امشب): عکس کامل ۲۳.۲ ثانیه طول می‌کشد، ولی کاربر می‌تواند
در کمتر از ۲ ثانیه اولین تصویر را ببیند. زیرساخت پلکانی
(thumbhash → پیش‌نمایش → اصلِ تأییدشده) ساخته و تست‌شده است؛ مسیر
پیش‌فرضِ UI هنوز منتظر کامل‌شدن می‌ماند.

طرح: ویجت تصویر پلکانی که هر سه پله را به‌ترتیب نمایش می‌دهد، به‌علاوه
تست تایم‌لاین که ثبت می‌کند هر پله در چه میلی‌ثانیه‌ای روی صفحه آمد.

```
verify: bash tools/phase6/gates/gate_p3_progressive.sh
exit 0 فقط وقتی: تست تایم‌لاین نشان دهد پله‌ی اول پیش از پله‌ی آخر و
زیر آستانه‌ی ثبت‌شده ظاهر شده و هر سه پله رخ داده‌اند.
```

## قدم ۴ — پریتیِ هم‌طولِ پنجره‌ای برای PTT (ارزش ۹، بذر RLNC)

مسئله (عدد امشب): در ماتریس دستگاه، PTT نسبت ۰.۱۶۷ و بیشترین سکوت
۴۰.۷ ثانیه داشت — یعنی وقتی باندلی گم می‌شود، صدا تا باندل بعدی
قطع است.

طرح: روی هر پنجره‌ی N باندل، یک باندل پریتیِ هم‌طول (XOR) فرستاده
می‌شود؛ گیرنده با از دست دادن حداکثر یکی از N+1، آن یکی را بازمی‌سازد.
این همان چیزی است که «پریتی یک‌بایتی» نمی‌توانست انجام دهد و شب قبل
ریاضی‌اش رد شد. هزینه: ۱/N افزایش نرخ — که باید در بودجه بنشیند.

```
verify: bash tools/phase6/gates/gate_p4_parity.sh
exit 0 فقط وقتی: هارنس ۲۰۰بذری نشان دهد نسبت بازیابی‌شده به‌طور
معنادار از حالت بدون پریتی بهتر است و نرخ سیم زیر بودجه بماند؛
هر دو عدد در tools/dossier/parity_matrix.tsv.
```

## قدم ۵ — مترِ صادق سلامت لینک + ممیزی نمودار فعلی (ارزش ۸.۵)

مسئله: نمی‌دانیم نمودارهای فعلی UI به شمارنده‌های واقعی وصل‌اند یا
نمایشی — و این دقیقاً همان چیزی است که یک داور بیرونی اول امتحان
می‌کند.

طرح: ابتدا ممیزی مکانیکی (هر ویجت نمودار → منبع داده‌اش؛ نتیجه در
TSV)، سپس یک متر که از شمارنده‌های واقعیِ موجود تغذیه می‌شود:
rtt پروب، دیتاگرام‌های ارسالی/دریافتی، نسبت تحویل.

```
verify: bash tools/phase6/gates/gate_p5_meter.sh
exit 0 فقط وقتی: ممیزی هر نمودار را با منبعش فهرست کرده باشد و تست
متر نشان دهد مقدارِ نمایش‌داده‌شده با شمارنده‌ی واقعی برابر است.
```
